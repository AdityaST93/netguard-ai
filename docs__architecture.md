# NetGuard AI — Architecture

## Pipeline

```
Network Traffic ──▶ Data Analysis ──▶ AI/ML Detection ──▶ Threat Alert ──▶ IP Block / Response
   (capture)         (feature build)      (RandomForest)      (alert_manager)   (ip_blocker)
```

1. **Traffic source** (`core/traffic_capture.py`)
   - Demo/CI mode: replays flow records from `data/sample_traffic.csv` (synthetic, generated by
     `ml/generate_synthetic_data.py`, styled after NSL-KDD/CICIDS-style flow features).
   - Optional live mode: `scapy`-based packet sniffing (`live_capture`), disabled by default,
     gated behind `LIVE_CAPTURE_ENABLED=True` and requires root/`CAP_NET_RAW`.

2. **Feature set** (10 flow-level features): `duration, src_bytes, dst_bytes, packet_count,
   packets_per_second, avg_packet_size, syn_flag_count, unique_dst_ports, same_src_conn_count,
   tcp_error_rate`.

3. **Detection model** (`ml/detector.py`, `ml/train_model.py`)
   - `RandomForestClassifier` (scikit-learn), multi-class: `normal`, `port_scan`, `dos`,
     `brute_force`, `ddos`.
   - Features are standardized with `StandardScaler` before inference.
   - Model + scaler persisted to `models/*.pkl` via `joblib`.

4. **Alerting** (`core/alert_manager.py`)
   - Every non-`normal` prediction becomes a structured alert (timestamp, source IP, threat
     type, confidence, derived severity) appended to `data/alerts.log` (JSON lines) and kept
     in an in-memory ring buffer for the dashboard.

5. **Response** (`core/ip_blocker.py`)
   - Tracks a persisted blocklist (`data/blocked_ips.json`).
   - Manual blocking via the dashboard/API always available.
   - Automatic blocking (`AUTO_BLOCK_ENABLED=True`) triggers once an IP accumulates
     `BLOCK_AFTER_N_ALERTS` threat alerts.
   - If enabled and `iptables` is present with sufficient privileges, a real `DROP` rule is
     applied; otherwise blocking is tracked at the application layer only (safe no-op).

6. **Serving layer** (`app.py`)
   - Flask REST API + server-rendered dashboard (Jinja2 templates, vanilla JS, no build step).
   - `/api/simulate` is the easiest way to see the whole pipeline run end-to-end.

## Why synthetic data?

Public IDS datasets (NSL-KDD, CICIDS2017, UNSW-NB15) are large downloads and licensing varies.
`ml/generate_synthetic_data.py` procedurally generates flow records with feature distributions
that mimic the shape of normal vs. attack traffic in those datasets (heavy SYNs + many unique
destination ports for a port scan, huge packet-per-second bursts for a DoS/DDoS, repeated
short connections to one port for a brute force, etc.), so the whole pipeline trains and runs
without any external downloads. Swapping in a real dataset only requires producing a CSV with
the same `FEATURE_COLUMNS` + `label` + `src_ip` schema and re-running `train_model.py`.

## Extending to production

- Replace `traffic_capture.replay_from_csv` with a real flow exporter (NetFlow/sFlow/Zeek logs)
  feeding `process_record()` in `app.py`.
- Swap `RandomForestClassifier` for a model retrained on real, labeled traffic from your network.
- Put the Flask app behind a real WSGI/ASGI stack (this repo already ships `gunicorn` +
  a `Dockerfile`) and a reverse proxy (nginx/Caddy) with TLS.
- Move `alerts.log` / `blocked_ips.json` to a real database if you need multi-instance
  deployment or long retention.
